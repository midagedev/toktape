# toktape 설계·스펙 문서

*2026-09-13. 인계 문서 `docs/research/00-handover-brief.md`(rig-log에서 측정한 교훈)와 같은 날 Gemini로 돌린 조사 세 편(`docs/research/01~03`)을 바탕으로 리드가 정리했다. 조사 보고의 별 개수·업보트 수는 2026-09-13 기준이고 한 달이면 낡는다. 결정은 사용자가 "toktape가자 이 방향으로"로 수용한 것이며, 아래 §1이 그 방향의 원문이다.*

## 0. 한 줄 정의

**toktape는 로컬 LLM 서빙의 블랙박스 테이프다.** 돌고 있는 llama-server에 붙어 프롬프트 하나를 보내고, 그 한 번의 실행에서 모델이 어디에 놓였는지(VRAM·RAM·NVMe), 프로세스가 실제로 뭘 만졌는지(RSS·매핑·미적재·토큰당 major fault), 요청이 얼마나 빨랐는지(prompt/decode tok/s·TTFT·캐시 히트), 그리고 토큰 텍스트 자체를 한 화면에 보여 준다. 실행은 전부 `.tape` 런 파일로 남고, 그 파일에서 결과 카드·GIF/mp4·비교 diff를 몇 번이든 다시 뽑는다.

세 목표와 각각의 한 줄 해법:

| 목표 | 해법 |
|---|---|
| 누구나 자기 리그의 머니샷을 쉽게 | 녹화 산술(VHS·fps·sleep)을 사용자에게 시키지 않는다. 런 파일에서 헤드리스로 렌더한다 |
| 바이럴이 쉽게 | 터미널 미학이 곧 신뢰의 신호다. 고정 레이아웃의 결과 카드가 GIF보다 오래 산다 |
| 실제 튜닝에 유용 | 비교가 일급 기능이다. `ab`(두 서버 동시)와 `compare`(두 런 사후 diff) |

## 1. 이미 내린 결정

이전 세션(tokenlab 디렉터리)에서 내려졌고 디스크에는 없던 결정이다. 여기가 원본이다.

1. **언어는 Go, 화면은 TUI.** 정적 바이너리 하나를 scp 하면 끝나야 "누구나"의 절반(설치 비용)이 사라진다. charm 생태계(bubbletea·lipgloss)가 east-asian width를 처리하고, VHS도 같은 집안이라 폴백 녹화 경로가 자연스럽다. GGUF 헤더 파서와 배치 추정(gpustack/gguf-parser-go), nvml 바인딩(NVIDIA/go-nvml, cgo 없이 dlopen)이 이미 Go에 있다.
2. **제품의 본체는 UI가 아니라 런 파일이다.** 런 중에 토큰별 타임스탬프와 샘플을 전부 기록하고, 카드·GIF·mp4·리포트는 그 파일에서 사후에 렌더한다. 남의 런 파일도 같은 룩으로 다시 그릴 수 있어야 비교 문화가 생긴다.
3. **웹은 조작 UI가 아니라 산출물이다.** v1에는 서버 띄우는 웹 앱이 없다. 여러 런을 훑는 용도는 런 파일에서 뽑는 단일 `report.html`로 충분하다. — **2026-09-18 재결정(사용자)**: 조작 UI가 아니라는 절반은 그대로다. 웹은 여전히 버튼이 아니라 기록을 다시 그리는 자리다. 뒤집힌 절반은 "서버가 없다"쪽이고, 이유는 `report.html`이 답하지 못하는 요구 둘이 나왔기 때문이다 — **남에게 링크 하나로 보여주기**와 **기계를 옮겨 다니며 내 실험을 이어서 적기**. 파일은 링크가 아니고, 한 기계 안에서만 산다. 설계는 §9.
4. **카드가 바이럴의 단위다.** Speedtest 결과 카드처럼 한 눈에 같은 도구인 걸 알아보는 고정 레이아웃. 텍스트판(Reddit 코드블록)·PNG(X)·JSON(비교)이 같은 데이터에서 나온다.
5. **헤드리스 렌더는 asciicast 경유가 기본.** 런 파일 → asciicast v2 → agg(GIF) 또는 Go에서 직접 프레임 PNG → ffmpeg(mp4). 프레임 수와 길이는 토큰 수와 속도에서 유도한다. VHS는 남의 테이프 호환용 폴백이다.
6. **토큰별 타임라인은 서버 수치로 그린다.** llama-server 요청에 `timings_per_token: true`를 주면 매 청크에 timings가 실린다. 클라이언트 벽시계는 교차 검증용이다.
7. **이름은 toktape.** 동명 GitHub 저장소 0, `.dev`·`.com` 비어 있음(2026-09-13 조회). `record / play / card / ab / compare` 동사가 이름에서 바로 나온다. tokenlab은 검색이 크립토·상용 API로 새서 버렸다.
8. **구현 순서**: ① 런 파일 스키마와 레코더 → ② 카드 렌더 → ③ TUI live 화면(v41-demo 패리티가 첫 게이트) → ④ 헤드리스 GIF/mp4 → ⑤ A/B·compare·HTML 리포트.
9. **동시 세션은 처음부터 일급이다** (사용자 지시 2026-09-13 "멀티 세션을 감당해내는 것도 트렌드, 처음부터 고려"). 에이전트 워크로드는 서버를 여러 세션이 동시에 때린다. 런은 "요청 하나"가 아니라 "동시 요청 N개 + 집계"이고, N=1이 특수 사례다. 스키마(`tape.Tape.Requests`, `Summary.Concurrency`, `Summary.Aggregate`), TUI(스트림 N개 표시), 카드("N × 스트림당 tok/s = 합계 tok/s", TTFT p50/p95, 슬롯 점유 최대), CLI(`--sessions N`, 기본 프롬프트 세트. 2026-09-14 `--concurrency`에서 이름을 바꿨다 — `-n`은 llama-bench처럼 생성 토큰 수이고, 세션은 8을 넘기려면 `--max-sessions`로 같은 숫자를 한 번 더 말해야 한다)가 모두 이 형태를 따른다. 머니샷 후보: "내 리그가 에이전트 8개를 동시에 몇 tok/s로 받아내는가".

10. **시각 품질이 제품이다** (사용자 지시 2026-09-13 "얼마나 고져스할지가.. 최소 crush 이상이면서 촌스럽지는 않아야"). TUI·PNG 카드·클립은 charmbracelet/crush 이상의 완성도를 기준으로 삼고, 모든 영역이 살아 숨쉰다(막대 이징, 커서 호흡, 스파크라인 스크롤, prefill 스피너, 활성 스트림 강조). 단 결정 10과 충돌하지 않게 **애니메이션은 벽시계가 아니라 클립 시간 t의 순수 함수**다 — 재생·GIF에서 그대로 재현된다. 시각 트랙이 끝날 때마다 리드가 실제 렌더 이미지를 직접 보며 조정하는 E2E 루프를 여러 차례 돈다.

**북극성**(사용자 지시 2026-09-13): 모든 결정은 "머니샷을 LocalLLaMA 커뮤니티에 올렸을 때 당장 써보고 싶어져야 하고, 실제로 쉽게 써서 결과물이 나와야 한다"로 잰다. 열린 질문의 답도 이 기준으로 리드가 정했다(§6).

## 2. 조사가 말하는 것 — 왜 사람들이 쓰고 싶어할 것인가

세 조사가 독립적으로 같은 곳을 가리킨다. 요약하면 **"왜 내 decode가 느린가"에 답하는 도구가 없다**는 것이다.

**수요 쪽(`01-demand-signals.md`)**. 2026년의 로컬 서빙은 "VRAM에 들어가나"의 이분법이 아니라 GPU·RAM·NVMe 3층 배치의 공학이 됐다. 가장 많이 반복되는 질문과 그 근거는 이렇다.

- **페이지 폴트로 인한 멈춤.** DeepSeek R1 671B를 64 GB RAM에서 mmap으로 돌린 글(1,332 업보트)이 촉발한 혼란: VIRT 400 GB를 보고 "RAM에 다 올렸다"고 믿고, 문장 중간에 얼어붙는 이유를 모른다. 토큰당 major fault 스파크라인이 이 질문에 한 눈에 답한다. 인계 문서도 "클립에서 가장 많이 본 것"이 이 스파크라인이라고 적었다.
- **VRAM 잠식.** `-b 4096 -ub 4096`이 컴퓨트 버퍼로 VRAM을 먹어 `--fit on`이 expert 레이어를 조용히 RAM으로 내렸고 68 → 38 tok/s가 됐다(RTX 5080 실험 글, 592 업보트). 지금 도구는 "VRAM 95%"만 보여 준다. 가중치·KV·컴퓨트 버퍼를 나눠 보여야 한다.
- **prefill과 decode의 혼동.** 전체 시간을 출력 토큰으로 나눠 올린 잘못된 벤치가 흔하다. TTFT·prompt tok/s·decode tok/s를 분리하는 것 자체가 기능이다.
- **캐시 히트 불명.** 시스템 프롬프트 한 글자 차이로 prefix 캐시가 미스 나도 사용자는 모른다. 히트 비율 배지가 필요하다.
- **투기 디코딩·MTP 수락률.** Qwen3.6 35B MTP로 12 GB에서 80 tok/s를 낸 글(674 업보트)의 핵심 고민은 draft 수락률이 보이지 않는다는 것이다. 수락률이 40~50% 아래면 오히려 느려진다.
- **A/B.** 양자화·컨텍스트·스레드 수를 바꿔 가며 손으로 표를 만드는 사람들(club-3090, 2,229 스타). `compare`가 이걸 대신한다.

**산출물 쪽(`02-sharing-artifacts.md`)**. 지금 커뮤니티가 쓰는 증거는 셋이다: llama-bench markdown 표, nvidia-smi 스크린샷, `ollama ps` 덤프. 각각 한 조각씩만 증명한다. llama-bench는 서버 HTTP 스택·연속 배칭·prefix 캐시를 우회하고 프로세스 메모리를 모르며, 업스트림 PR들이 VRAM/RAM 열(#23208), 유효 대역폭 열(#28459), TTFT/ITL(#15643)을 따로따로 덧붙이고 있다. 즉 사람들은 이미 llama-bench 표에 toktape 카드의 필드를 하나씩 끼워 넣으려 하고 있다. 논쟁을 부르는 누락 5종은 pp/tg 미분리, Flash Attention 상태 누락, cold/warm 캐시 미표기, prefix 캐시 히트 미표기, `-b/-ub` 누락이다. 카드가 이 다섯을 항상 인쇄하면 댓글 50개짜리 싸움이 사라진다.

**범위 쪽(`03-audience-and-scope.md`)**. Ollama가 사용자 수는 압도적(스타 18만, Docker pull 1.7억)이지만 배치와 `/proc` 그림이 빈약해 카드가 심심해진다. 튜닝 담론의 진앙은 r/LocalLLaMA(82만 구독, r/ollama의 6배)이고 거기서 플래그를 만지는 사람은 llama-server와 ik_llama.cpp를 쓴다. Apple Silicon은 별도의 큰 바이럴 벡터다(M5 Ultra 512 GB 글 1,651 업보트, "5090이 5090달러" 글 1,640 업보트). `sudo powermetrics` 없이 IOReport로 읽는 선례(macmon·btop)가 있고 `task_vm_info.pageins`가 majflt의 짝이다. Windows 튜너는 대부분 WSL2라 `/proc` 의미론이 그대로 통한다.

## 3. 스펙 — 우선순위 붙인 기능 목록

각 항목은 "왜 원하는가(근거)"와 "어떻게 구현하는가(훅)"를 함께 적는다. 근거가 없는 기능은 넣지 않았다. llama-server 필드명(`timings_per_token`, `return_progress`/`prompt_progress`의 `total`·`cache`·`processed`·`time_ms`, `timings.cache_n`, `/apply-template`)은 2026-09-13 업스트림 `tools/server/README.md`에서 확인했다.

### 3.3 Could (v1 이후, 근거는 있지만 지금 넣으면 범위가 샌다)

- **Ollama 어댑터.** 사용자 수는 가장 크지만 스트림 중 토큰별 timings가 없어 스파크라인이 사후 평균으로 퇴화한다. `/api/ps`의 `size_vram / size`로 오프로드 비율 카드까지는 싸다(조사 03 §2.2·순위 6). **열린 질문(§6)**.
- **vLLM / SGLang.** `/metrics`의 `vllm:time_to_first_token_seconds`·`sglang:cache_hit_rate`가 있어 어댑터는 쉽지만, 연속 배칭 다중 테넌트라 "한 런"의 의미가 다르다.
- **LM Studio.** SSE 이벤트 단계(`model_load.progress → prompt_processing.progress → message.delta`)가 우리 라이프사이클과 잘 맞는다.
- **`report.html`.** 여러 런을 브라우저에서 훑는 정적 단일 파일. §1 결정 3.
- ~~**gist·rig-log 게시.** 인계 Could.~~ → §9로 승격(2026-09-18). gist는 링크는 주지만 기록을 다시 그리지 못하고, 검색도 저널도 되지 않는다.
- **네이티브 Windows.** `/proc` 없음, `SIGWINCH` 없음, ETW는 관리자 권한. WSL2 안내로 대신한다(조사 03 §4).
- **AMD ROCm / Intel Arc.** `rocm-smi` 인터페이스가 배포판마다 갈린다.
- **KV 캐시 팽창 그래프.** 컨텍스트 증가에 따른 KV 메모리와 여유(조사 01 순위 9). M6의 3분할이 먼저다.

## 4. 결과 카드 계약

카드는 "논쟁을 끝내는 필드"를 빠짐없이, 같은 자리에 인쇄한다. 조사 02 §5의 필수 6종과 논쟁 5종을 그대로 계약으로 삼는다.

**항상 인쇄하는 필드(순서 고정)**

1. 헤더: `toktape vX.Y` · 런 ID(날짜-순번)
2. 모델: 파일명 · 정확한 양자화 서브타입(`Q4_K_M`, `IQ4_NL`, `UD-Q4_K_M` — "Q4"로 줄이지 않는다) · 파일 크기
3. 엔진: `llama-server` 빌드 번호 + 커밋 해시 · OS 커널
4. 리그: GPU 수×모델·VRAM · CPU · RAM 용량과 속도(`DDR5-6000`) — RAM 속도는 부분 오프로드에서 결정적(조사 02 순위 7)
5. 속도 3종: decode tok/s(+ 유효 GB/s, S6) · prefill tok/s(+ TTFT ms, 프롬프트 토큰 수) · 설정 컨텍스트와 테스트 in/out 토큰 수
6. prefix 캐시 히트 % (`0.0% (Cold Run)` 또는 `78% (400/512)`)
7. 메모리 배치: VRAM 막대(가중치|KV|버퍼) · 호스트 RSS · NVMe 미적재 GB · **majflt/token**
8. 호스트 상태: GPU별 온도·전력 · throttled · **contended: yes/no**
9. 플래그 한 줄: `-ngl -fa -b -ub -ctk -ctv --load-mode -ot ...` (Flash Attention과 `-b/-ub`는 생략 불가)
10. 푸터: `VERIFIED BY TOKTAPE` · 저장소 URL

**텍스트판**: 유니코드 박스, 72열 고정(Reddit 모바일에서 줄바꿈 안 나는 폭). 한글 포함 시 east-asian width 2로 계산하고 ANSI를 벗긴 뒤 잰다(교훈 5). 하단에 llama-bench 호환 markdown 표 한 블록을 붙여 기존 문화에 얹는다.

**PNG판**: 1200×675(16:9, X·Reddit OpenGraph). 어두운 배경, 큰 숫자 둘(decode·prefill)이 히어로, 그 아래 메모리 계층 막대와 majflt 스파크라인, 하단 4열 메타데이터 그리드. 색 계약은 구현 스펙에서 hex로 못박는다.

**JSON판**: `RunSummary` 그대로. `compare`의 입력.

## 9. 공유와 저널 — `tape.midagedev.com`

*2026-09-18 결정. 사용자가 두 요구를 같은 물건으로 묶었다 — "남에게 공유한다는 의미와 자기 실험기록을 저널로 적는다는 의미 모두 살리자, 이건 나한테도 필요한거라서". 리더보드는 명시적으로 아니다("리더보드 만들고 싶은건 아냐 다만 사양과 모델 등으로 검색해 볼 수 있게는 하고 싶어", 2026-09-18; 그 전날에도 "밴치마크 리더보드를 만들고 싶은게 아니라").*

### 9.1 무엇인가

**기록을 호스팅한다. 픽셀이 아니라.** asciinema는 터미널 출력 스트림을 호스팅하고, 벤치마크 사이트는 숫자만 받고, `vhs publish`는 구워진 GIF를 올린다. 구조화된 기록을 올려두면 그게 스스로 다시 렌더되는 곳은 없다.

실측이 그 차이를 그대로 보여준다(히어로 클립 하나, 2026-09-17):

| 산출물 | 크기 | 되돌릴 수 있나 |
|---|---|---|
| 기록(`.toktape`) | **55 KB** | 카드·GIF·cast 전부 다시 뽑힌다 |
| asciicast v2 | 5.9 MB (gz 118 KB) | 숫자가 글리프라 OCR 말고는 없다 |
| GIF | 4.1 MB | 없다 |

가장 작은 것이 가장 많이 안다. 픽셀이 아니라 사건이기 때문이다.

### 9.2 두 얼굴, 하나의 기록

같은 업로드가 두 가지로 쓰인다.

- **공유** — 링크 하나를 남에게 준다. 미리보기는 PNG 카드가 OG 이미지로 뜨고, 열면 기록이 다시 그려진다.
- **저널** — 내 실험 기록이 기계를 옮겨 다녀도 이어진다. 로컬 원장(`runs.tsv`·`toktape log`·`--tag`/`--note`, TTP-19)의 바깥 짝이다.

저널이 되려면 기록에 주인이 있어야 한다. 계정은 만들지 않는다 — **첫 publish 때 토큰을 발급받아 저장**하고, 그 토큰이 네임스페이스를 소유한다. 토큰이 있으면 내 저널로 들어가고, 없으면 일회성 업로드다. 같은 엔드포인트, 다른 귀속. OAuth도 로그인 화면도 없어서 "한 줄이면 공유"가 유지된다. 토큰이 사는 곳은 §9.3의 설정 파일이다.

### 9.3 기본값은 공개, 경고는 한 번, 설정은 한 파일

**둘 다 기본 공개다**(사용자 결정 2026-09-18: "기본은 공개 필요하면 프라이빗", "텍스트도 기본 공개"). 가시성은 `--private`로 검색에서 빠지고 추측 불가능한 URL로만 열린다. 본문 텍스트 — 프롬프트 전문과 생성 텍스트 전문(히어로 기준 스트림당 1,710자) — 도 기본으로 올라간다. 리플레이가 의미를 가지려면 화면에 글자가 있어야 하고, 기본을 끄면 서비스의 본체가 기본으로 비어 있게 된다.

대신 **처음 한 번은 경고한다**(사용자 결정 2026-09-18). 첫 `publish`에서 무엇이 올라가는지 — 본문 텍스트, 모델 경로, 서버 argv — 를 보여주고 계속할지 묻는다. 두 번째부터는 묻지 않는다.

토큰을 저장해야 하므로 어차피 상주 파일이 하나 생긴다. 토큰과 설정은 **같은 파일**이다 — 오늘 toktape에는 설정을 읽는 코드 경로가 0건이고(`~/.toktape/`는 런 디렉터리일 뿐, 2026-09-18 확인) 이 기능이 그 첫 소비자다:

```
~/.toktape/config.toml
  token = "…"                         # 저널 네임스페이스의 주인 (§9.2)
  first_publish_warning_seen = true   # 경고를 한 번 봤다
  publish_text = false                # 옵트아웃: 이 기계에서는 본문을 빼고 올린다
  host_label = "workstation"          # --host-label의 상주판
```

파일 권한은 0600이다. 토큰이 들어 있으므로 그 자체가 자격증명이고, 읽기 실패나 부재는 "설정 없음"이지 오류가 아니다.

플래그가 설정을 이긴다(`--with-text`/`--no-text`). 옵트아웃은 기계 단위이지 업로드 단위가 아니다 — 매번 기억해서 붙여야 하는 안전장치는 안전장치가 아니다.

- 호스트명·절대경로는 가시성과 무관하게 항상 정화한다. `--host-label`(TTP-93)과 rig-log의 sanitizer가 이미 그 일을 하고 있으므로 **세 번째 경로를 만들지 않는다** — `internal/tape`에 공개용 뷰를 하나 두고 셋이 그것을 쓴다. 이 뷰는 스키마이므로 리드 소유다.

  **무엇을 지우는지는 여기가 정한다.** 기본이 공개이므로 공개용 뷰는 기본 발행에서 **거의 항등함수**여야 한다 — 지우는 것은 "사용자가 공유하려던 것일 리 없는 것"뿐이고, 판단은 뷰 구현이 아니라 이 표가 한다.

  | 필드 | 규칙 | 왜 |
  |---|---|---|
  | `host.hostname` / `server.host` | `hostname_source`가 `label`이면 그대로, 아니면 비운다(`hostname_source`도 함께) | 사용자가 직접 붙인 라벨은 공유하려고 붙인 것이다. 기계에서 읽은 이름은 아니다 |
  | `server.url` | 포트만 남긴다(`:8080`) | 호스트·IP는 장소이고, 포트는 설정이다 |
  | `server.args` | 플래그 이름은 그대로, 경로처럼 생긴 값은 basename으로 | argv는 카드가 인쇄하는 설정의 원본이다. 통째로 지우면 "무슨 플래그로 쟀나"가 사라진다 |
  | `model.path` | 비운다. `file_name`·`dir`은 남긴다 | 파일 이름과 변형 디렉터리는 모델 신원이고, 그 앞의 경로는 그 사람의 디스크다 |
  | `model.repo` 외 HF 필드 | 그대로 | 이미 공개된 것이다(§9.4) |
  | `warnings` | 경로처럼 생긴 조각을 basename으로 | 카드에 그대로 인쇄되는 문장이다 |
  | `tag` / `note` | 그대로 | 사용자가 고른 자기 말이다 |
  | 프롬프트·생성 본문 | 기본 유지. `publish_text = false` 또는 `--no-text`일 때만 비운다 | 기본 공개가 결정이고(위), 본문 없는 리플레이는 서비스의 본체가 빈 것이다 |

  경로 판정은 한 규칙이다: **`/`로 시작하거나 `\`를 포함하거나 `~/`로 시작하는 토큰**을 경로로 보고 basename만 남긴다. 상대 경로는 이미 장소를 말하지 않으므로 건드리지 않는다.
- `toktape publish --dry-run`은 올라갈 기록을 그대로 출력한다. 무엇이 공개되는지 필드 단위로 보여줄 수 있는 것이 구조화된 기록의 이점이고, 바이트 스트림인 asciinema·VHS가 못 하는 지점이다. 첫 실행 경고도 이 출력을 재사용한다.
- 지우는 길이 항상 있어야 한다. 저널 업로드는 §9.2의 토큰이 소유하므로 그것으로 지운다. 토큰 없이 올린 일회성 업로드는 그때 한 번 출력되는 삭제 토큰이 유일한 열쇠이고, 그 사실을 출력에 적는다.

### 9.4 검색 — 순위표가 아니다

기본 정렬은 최신순이고 **순위 열이 없다.** 필터는 모델·양자화·엔진·GPU·VRAM·호스트 클래스이고, 범위는 둘이다 — 공개 전체, 그리고 내 저널.

카드의 caveat이 행마다 따라간다. 카드가 `! 3 caveats`로 자격을 말하는 이유가 검색 결과에서 사라지면, 정렬만 없앤 리더보드가 된다.

**필터가 성립하려면 정규화가 먼저다.** 오늘 기록의 모델·엔진·GPU는 자유 문자열이다 — `/models/Qwen3.6-35B-A3B/Qwen3.6-35B-A3B-UD-Q6_K.gguf`와 다른 기계의 `Qwen3.6-35B-A3B-Q6_K`는 같은 모델이지만 다른 값이고, 그대로 색인하면 필터의 모든 값이 고유해서 아무것도 좁혀지지 않는다. 정규화가 필요한 축:

| 축 | 원본 | 정규화 |
|---|---|---|
| 모델 | 파일 경로·`/props`의 이름 | HF repo(증명된 경우) + GGUF 이름 규약 슬러그. 아래 참조 |
| 양자화 | `UD-Q6_K`, `IQ4_XS`, `MXFP4` … | 표준 라벨 + 가중치 비트 |
| 엔진 | kind + build/commit | 이름과 버전을 분리 |
| GPU | nvidia-smi 문자열 | 정규 모델명 + VRAM |
| 호스트 클래스 | 디바이스 목록 | GPU 수 × 모델, RAM 급 |

**모델 축은 우리가 만든 어휘를 쓰지 않는다**(사용자 2026-09-18: "정규화는 뭔가 허깅페이스 중심이 되어야 하지 않나"). 첫 구현은 파일명을 소문자로 내리고 양자화 꼬리를 떼는 슬러그였는데, 그건 아무도 안 쓰는 네 번째 어휘다. 실측(TTP-119, 2026-09-18)이 답의 모양을 바꿨다 — **repo id는 GGUF 안에 없다.** unsloth는 `general.repo_url`에 자기 org만 적고, bartowski는 아무것도 안 적고, 오래된 ggml-org 파일은 둘 다 없다.

진짜인 것은 둘이고, 둘은 **다른 질문**이라 필드도 둘이다.

- **`repo`** — "누구의 빌드인가". 정확한 HF repo id는 경로에만 있다. 파일이 HF 캐시(`…/hub/models--<org>--<repo>/snapshots/<sha>/`)에 있을 때만 증명되고, 그때만 `repo_source = "hf-cache"`와 함께 기록된다. 출처 없는 repo는 추측이므로 색인에 올라가지 않는다.
- **`model_id`** — "어떤 모델인가". GGUF 이름 규약(`general.basename` / `size_label` / `finetune`, ggml `docs/gguf.md`)을 규약 자신의 순서로 이어붙인 슬러그다. 양자화 배포자들이 규약의 어디까지를 basename에 접어 넣는지가 서로 다르기 때문에(unsloth `Qwen3-0.6B`, bartowski `Qwen3`, 둘 다 size_label `0.6B`) **basename이 이미 가진 조각은 다시 붙이지 않는다**. 이 한 줄이 우리가 더한 유일한 규칙이고, 그 결과 두 배포자가 같은 `qwen3-0.6b`로 모인다.

둘을 한 필드로 합치면 행마다 id의 의미가 달라지고, 그런 id로는 검색이 안 된다. `model_id_source`(`gguf` | `filename`)가 슬러그를 따라다니는 이유도 같다 — 파일명에는 fine-tune이 없다(양자화 태그가 그 자리를 차지한다, 실측). 이름에서 뽑은 id는 한 모델의 두 fine-tune을 합칠 수 있고, 그러면 안 되는 소비자는 이 필드로 구분한다.

세 가지 규율이 붙는다.

1. **정규화는 클라이언트(Go)에서, 스키마 옆에서 한다.** 인덱스를 뽑는 곳이 곧 스키마를 아는 곳이다(§9.6).
2. **원본을 지우지 않는다.** 인덱스는 정규값과 원본 문자열을 둘 다 들고, 정규화가 실패하면 그 필드는 빈 값이지 추측이 아니다 — "관측하지 않은 기본값을 찍지 않는다"가 여기에도 그대로 적용된다. 검색은 정규값이 없으면 원본 문자열 검색으로 떨어진다.
3. **정규화는 되돌릴 수 있다.** 기록 원본이 R2에 그대로 있으므로 표가 틀렸다고 밝혀지면 저장된 기록에서 인덱스를 다시 뽑으면 된다. 정규화 오류는 영구 손상이 아니다 — 이 설계에서 유일하게 되돌릴 수 없는 선택은 "본문을 안 받는 것"뿐이다.

### 9.5 표준 프롬프트 세트 — 비교가능성의 본체

순위표 없이 "비교"가 성립하려면 **같은 것을 돌린 기록끼리** 모여야 한다.

세트 자체는 이미 있다 — `internal/server/prompts.go`의 16개로, TTP-84에서 길이 양끝(prefill 측정이 되는 하한, 20 s 예산을 prefill이 다 먹지 않는 상한)을 실측해 다시 쓴 것이고 그 근거가 파일 주석에 남아 있다. 이 서비스가 요구하는 것은 새 세트가 아니라 **세트에 없는 세 가지**다.

1. **id와 버전이 없다.** 기록이 "무엇을 돌렸는지"를 말하지 못하면 검색이 비교 가능한 집합을 만들 수 없다. `prompts@v1`을 tape에 적고, **내용이 바뀌면 id가 바뀐다** — 같은 id를 단 두 기록이 사실 다른 일을 한 것이 되는 게 벤치마크 사이트들이 실제로 겪은 실패다. 사용자가 자기 프롬프트를 준 런은 id가 비고, 그건 "비교 집합에 없음"이지 결함이 아니다.
2. **산문이 거의 없다.** 16개 중 15개가 코드·설정·로그이고 산문은 포스트모템 하나다. 코드와 산문은 성질이 다른 부하다 — 실측(2026-09-18, Qwen3·Llama 3.1·gpt-oss 세 토크나이저)으로 이 세트의 가장 조밀한 코드가 토큰당 3.3자, 가장 산문에 가까운 것이 5.0자다. 한쪽으로 잰 tok/s를 다른 쪽에 적용하는 것이 정확히 이 도구가 막으려는 오해이므로, 산문 쪽을 늘려 축을 맞춘다(사용자 2026-09-18).
3. **CJK가 없다.** 전부 영어다. 한국어·일본어는 토큰당 글자 수가 달라 같은 512 토큰이 다른 화면 분량이 되고, 카드의 폭 계약(east-asian width)이 실제로 걸리는 것도 거기다. 한국어 프롬프트가 세트에 있어야 그 경로가 매일 돌아간다.

기존 주석이 못박은 제약은 그대로 지킨다: 서로 첫 단어부터 달라 동시 스트림이 프리픽스 캐시를 공유하지 않을 것, 재료가 먼저 지시가 나중일 것, 도구·파일·네트워크가 필요 없을 것, 채움말이 없을 것.

**2026-09-18 완료(TTP-112).** 셋 다 들어갔다. `server.PromptSetID = "prompts@v1"`을 세트가 자기 요청에 직접 찍고(레코더가 "`--prompts`가 없었으니 기본 세트였겠지"라고 추론하지 않는다 — 다른 호출자가 요청을 만드는 날 조용히 틀린다), 요청들의 값이 서로 다르면 그 런은 비교 집합이 없는 것이라 빈 값이다. id가 지키는 약속은 **해시 게이트**가 지킨다 — 프롬프트가 한 글자라도 바뀌면 빨강이고, 세트가 릴리스에 실렸으면 버전을 올리고 아니면 해시만 갱신하라고 테스트가 말한다.

내용은 5개가 늘어 21개다: 영문 산문 2, 한국어 2, 일본어 1. **순서도 세트의 일부다** — 런은 앞에서부터 Concurrency개를 보내므로 뒤에 붙이면 흔한 실행은 산문·CJK를 영원히 못 본다. 첫 한국어가 6번, 일본어가 14번이고 `-n 1`~`-n 4`는 영어로 남겼다.

길이 게이트는 바이트 그대로 두었다. **바이트/토큰이 스크립트에 거의 무관**하다는 것이 실측으로 나왔기 때문이다(코드 3.3~3.5, 영문 산문 5.1~5.2, 한국어 3.4~4.0, 일본어 4.1~4.6 — byte-level BPE라서 그렇다). 글자/토큰으로 쟀다면 한국어 1.4가 영어 5.1과 같은 대역에 들어올 수 없어 대역이 셋 필요했을 것이다.

### 9.6 구조 — Cloudflare, 그리고 Worker는 tape를 파싱하지 않는다

| 조각 | 역할 |
|---|---|
| R2 | 기록과 PNG 카드 원본 |
| D1 | 검색 인덱스 |
| Worker | 업로드, `/r/<id>`, `/r/<id>.png`(OG), 검색 |
| Static Assets | 플레이어 HTML과 wasm |

**설계의 핵심은 Worker가 기록을 해석하지 않는다는 것이다.** 업로드할 때 클라이언트(Go)가 인덱스용 메타데이터를 버전 붙은 타입으로 뽑아 같이 올리고, Worker는 저장과 질의만 한다. 스키마 주인은 `internal/tape` 하나로 남는다 — 측정된 0과 관측되지 않은 필드를 가르는 종류의 판단(TTP-103·109)이 TypeScript에 복제되면 두 곳에서 서로 다르게 틀린다.

Worker가 모르는 인덱스 스키마 버전은 **이름을 대며 거절한다.** 조용히 잘못 색인하지 않는다.

### 9.7 확장자 — `.tape`에서 `.toktape`로

Charm VHS가 `.tape`를 쓴다(별 20,878개, 그것도 터미널 GIF라는 같은 동네). VHS의 `.tape`는 *무엇을 칠지 적은 각본*이고 우리 것은 *무슨 일이 있었는지 적은 기록*이라, 뜻이 정반대인데 확장자가 같다. 사용자 본인이 "나는 charm용 포멧인 줄 알았는데"라고 했고, 그 착각 자체가 데이터다.

공개 서비스의 첫 문장이 "이건 연출된 녹화가 아니라 진짜 기록이다"인데 확장자가 이미 반대를 뜻하면 설명부터 시작해야 한다. 비용은 지금이 가장 싸다 — 코드에는 사실상 상수 하나(`internal/tape/io.go`의 `const Ext`)뿐이고 나머지는 문서·테스트 문자열이다.

**읽기는 둘 다, 쓰기는 `.toktape`.** 이미 `~/.toktape/runs/*.tape`를 가진 사람이 있고, `ls`와 최신 런 탐색이 양쪽을 모두 찾아야 한다.

### 9.8 브라우저 렌더 — wasm은 뒤 단계다

`internal/tui`·`internal/render`는 js/wasm으로 빌드된다. bubbletea를 import하는 파일은 `internal/tui/run.go` 하나뿐이라 거기에 `//go:build !js` 하나면 갈라진다(2026-09-17 확인, 2026-09-18 재확인). 렌더러가 하나로 유지되므로 카드가 두 곳에서 다르게 보이는 결함 계열이 열리지 않는다.

순서는 그래도 뒤다. 페이지는 **PNG 카드(92 KB)와 메타데이터로 즉시** 뜨고 — OG 이미지가 이미 그 카드라 미리보기가 공짜다 — "Replay"를 눌렀을 때만 wasm을 받는다. **공유 URL·검색·저널은 wasm 없이 출시된다.**

크기는 잴 수 있고, 재 보니 절반이 렌더와 무관한 짐이었다(2026-09-18, 사다리 실측):

| 구성 | raw | gzip | brotli |
|---|---|---|---|
| 지금 그대로 | 16.1 MB | 3.85 MB | 2.76 MB |
| GGUF 파서 제외 | 11.0 MB | 2.73 MB | |
| GGUF + chroma 제외 | **6.7 MB** | **1.82 MB** | **1.36 MB** |

귀속: Go wasm 빈 프로그램이 gz 756 KB이고 `internal/tape`는 거기에 22 KB를 더한다. 무게는 두 곳이다.

**하나는 GGUF 파서이고, 이건 wasm보다 큰 문제다.** `internal/placement/gguf.go`의 `ModelInfoFromFile`이 gpustack/gguf-parser-go를 끌고 오고(그와 함께 json-iterator·modern-go/reflect2·httpretty·ringbuffer), `internal/card`가 placement를, `internal/tui`가 card를 import하므로 **렌더 경로 전체가 그것을 진다.** 그런데 그 함수는 모델 파일을 디스크에서 읽는 녹화 시점의 일이고, 테이프에는 이미 placement 요약이 들어 있다. CLAUDE.md의 계약은 "모든 렌더러는 `*tape.Tape`만 읽는다"인데 실제 의존 그래프는 그렇지 않다. 파일 하나를 자기 패키지로 옮겨 레코더만 import하게 하면 된다(TTP-118, 2026-09-18 완료). **다만 이득은 브라우저에만 있다** — 배포되는 CLI는 레코더와 렌더러가 한 바이너리라 파서가 여전히 링크되고, 실제로 재 보니 linux/amd64 `-s -w`가 18,768,034 → 18,759,842바이트로 8 KB밖에 줄지 않았다. 리드가 "바이너리도 같이 가벼워진다"고 적었다가 측정으로 기각했다. 남는 이득은 번들과, 의존 그래프가 계약과 다시 일치한다는 사실이다.

**다른 하나는 chroma다.** `internal/tui/highlight.go`가 `chroma/v2/lexers`를 쓰는데 그 패키지는 모든 언어의 렉서 정의를 embed한다(gz 835 KB). 접점은 좁다 — `lexers.Get`과 `Tokenise` 두 줄, 그리고 토큰 타입을 8개 `codeClass`로 접는 `classOf` 하나뿐이다. 그래서 웹 빌드에서는 빌드 태그로 가벼운 구현을 끼운다: 포팅이 아니라 파일 교체이고, 계약이 "8개 클래스"라 대체 구현이 만족시켜야 할 것도 그게 전부다. 터미널 쪽은 chroma를 그대로 쓴다.

TinyGo는 쓰지 않는다. lipgloss와 reflect 의존이 있어 그건 별도 프로젝트가 된다.

Cloudflare 제약: wasm은 Worker 스크립트(3~10 MB)가 아니라 Static Asset(파일당 25 MiB)으로 나간다. 전송은 브로틀리이므로 위 표의 마지막 열이 실제로 내려가는 크기다.

### 9.9 단계

1. **확장자** `.toktape`(TTP-111) + 양쪽 읽기 + 히어로 재렌더.
2. **프롬프트 세트에 id와 버전**(TTP-112, 2026-09-18 완료), 그리고 산문·한국어 보강. 인덱스가 비교 집합을 만들려면 이게 먼저 tape에 들어와 있어야 한다.
3. **렌더 경로에서 GGUF 파서 분리**(TTP-118). wasm의 절반이자, 배포 바이너리의 같은 짐이다.
4. **인덱스 타입과 정규화**(TTP-113 + TTP-119, 2026-09-18 완료) — 버전 붙은 Go 타입, 정규값과 원본을 함께, 실패는 빈 값. 서버가 아니라 여기서 판단이 끝난다. 모델 축은 TTP-119에서 HF·이름 규약으로 다시 놓았다(위 §9.4).
5. **정화 뷰와 `toktape publish`**(TTP-114) — `internal/tape`의 공개용 뷰, 설정 파일과 첫 실행 경고, `--dry-run`, `--private`, `--no-text`, 삭제 토큰, 토큰 발급.
6. **Worker**(TTP-115) — R2·D1·업로드·`/r/<id>`·OG 이미지·검색. 코드는 이 레포 `web/`에 둔다(사용자 결정 2026-09-18): wasm과 인덱스 타입이 같은 커밋에서 빌드된다.
7. **wasm 플레이어**(TTP-116) — 크기 레버를 재고 나서.
