## The rules the repository set for itself

docs/git-workflow.md in arborbank/ledger, the whole of the section on branches:

~~~text
## Branches

main is trunk. Everything else is a branch off it, and branches are
short-lived: days, not weeks.

feature/* branches are shared when two people work on one thing. Say
so at standup, so nobody rewrites underneath anyone.

Never rewrite history that someone else may have pulled. If a shared
branch must be rebased, coordinate in the channel first.

Force-push only to branches you alone own, and with --force-with-lease,
never bare --force.

A diverged pull is git refusing to guess. Pick merge or rebase once,
in your configuration, so the refusal never surprises you; we
standardise on pull.rebase false, and feature-branch merge commits
are squashed when the pull request lands.
~~~

And the CI workflow those rules refer to, .github/workflows/ci.yml, in full:

~~~yaml
name: ci
on:
  pull_request:
  push:
    branches: [main]

jobs:
~~~

The rule that names --force-with-lease has been in that file since before anyone now on the team joined; it is not enforced anywhere, and nothing in Sam's configuration would have reminded him of it.
